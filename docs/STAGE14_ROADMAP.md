چهار سندِ کارفرما (بسته‌ی `dashboard.rar`، ۲۰۲۶-۱۰-۱۳)، هر کدام **کامل** خوانده شد:

| ---------------------- | -------------------------------------- | ------------------------------------------------- |
| داشبورد ثبت‌نامِ اولیه | ۱۴ بخش، ۲۴ بند، DoD ِ ۱۸ بندی          | [STAGE13_ROADMAP.md](STAGE13_ROADMAP.md) بخشِ ۶.۲ |
| داشبوردِ مدیر          | ۳۲ بخش، ۳۸ بند، ماتریسِ پذیرشِ ۲۵ حوزه | همان، ۶.۳                                         |
| داشبوردِ واحد          | ۲۷ بخش، ۱۵۳ بند                        | همان، ۶.۴                                         |
| داشبوردِ سوپر ادمین    | ۲۳ بخش، ۹۰ بند                         | همان، ۶.۵                                         |

سندِ پنجمِ همان بسته («داشبورد های آزمایشی») در مرحلهٔ ۱۳ اجرا و بسته شد ([STAGE13_ROADMAP.md](STAGE13_ROADMAP.md) ۵.۱۲).

**روش:** هر بند با کدِ واقعی (مدل، migration، مسیرِ API، کنترلر، صفحه‌ی رابط، آزمون) تطبیق داده شد. وضعیت‌ها در این سند
**وضعیتِ فعلیِ کد** است، نه وعده:

| برچسب       | معنا                                                                               |
| ----------- | ---------------------------------------------------------------------------------- |
| ✅ موجود    | پیاده‌سازی و آزمون در مرحله‌های قبل؛ در ۱۴ فقط با الزامِ تازه‌ی سند بازسنجی می‌شود |
| 🟡 جزئی     | بخشی هست؛ شکافِ مشخص نوشته شده                                                     |
| ⛔ نیست     | هیچ مدل، مسیر یا صفحه‌ای نیست                                                      |
| ❓ تصمیم    | پیش از اجرا تصمیمِ کارفرما لازم است (بخشِ ۲)                                       |
| 🌐 محیطی    | فقط با سرویس یا محیطِ واقعی سنجیدنی است (درگاه، پیامک، Safari، سرور)               |
| 🚫 عمداً نه | INTENTIONALLY NOT BUILT با دلیلِ ثبت‌شده                                           |

چرخه‌ی هر بند در اجرا (هر چهار سند): Inventory → Inspect → Fix → Test → Adversarial → Regression → Documentation.

## ۷. موجودیت‌های تازه‌ی مشترک

چند قابلیت در هر چهار سند مشترک‌اند و **یک بار** ساخته می‌شوند — نه چهار نسخه:

| موجودیت                       | سندها                       | نکته‌ی معماری                                                                                       |
| ----------------------------- | --------------------------- | --------------------------------------------------------------------------------------------------- |
| کاتالوگِ قابلیت (Entitlement) | هر چهار                     | کلیدِ canonical برای هر قابلیت؛ پلن فقط مجموعه‌ای از کلیدها؛ بررسی در middleware/Policy، Job و فایل |
| مجوزِ مدیرِ فرعی              | مدیر، واحد، سوپر ادمین      | مجوزها روی عضویتِ مدیریتی، نه روی حساب؛ ابطالِ فوری                                                 |

| دفترِ صندوق                   | مدیر، واحد، سوپر ادمین      | Ledger ِ تغییرناپذیر، جدا از کیف پول؛ وصولِ قبض دو اثرِ جدا می‌سازد (بدهکاریِ کیف و ورودیِ صندوق)   |
