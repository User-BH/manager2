# راهنمای توسعه‌دهنده

این سند برای کسی است که تازه واردِ این مخزن شده و می‌خواهد **کار کند**، نه
اینکه معماری را مطالعه کند. برای آن دو، [BACKEND_STRUCTURE.md](BACKEND_STRUCTURE.md)
و [FRONTEND_STRUCTURE.md](FRONTEND_STRUCTURE.md) هست.

---

## راه‌اندازی

پیش‌نیازها: **PHP 8.4**، **Node 24**، و MySQL 8 یا MariaDB.

```bash
composer install
npm install
cp .env.example .env
php artisan key:generate
php artisan migrate --seed
```

سپس دو ترمینال:

```bash
php artisan serve
```

```bash
npm run dev
```

> ⚠️ **بدونِ `npm run build` یا `npm run dev`، تست‌های PHP هم می‌افتند.**
> صفحهٔ فرود تصویرِ LCP را با `Vite::asset()` بارگذاری می‌کند و آن تابع
> بدونِ `public/build/manifest.json` استثنا پرتاب می‌کند. همین ترتیب در CI
> هم اجباری است و `backend` وابسته به `frontend` تعریف شده.

### تنظیماتی که احتمالاً باید عوض کنید

بیشترِ `.env.example` برای توسعهٔ محلی آماده است. سه مورد جای فکر دارند:

| کلید                      | چرا                                                                                       |
| ------------------------- | ----------------------------------------------------------------------------------------- |
| `DB_*`                    | مشخصاتِ MySQL محلی                                                                        |
| `SMS_DRIVER`              | پیش‌فرض روی درایورِ آزمایشی است؛ برای پیامکِ واقعی کلید لازم است                          |
| `PAYMENT_SANDBOX_ENABLED` | ⚠️ در محیطِ آزمایشی حتماً `true`، وگرنه پرداختِ آزمایشی روی درگاهِ **واقعی** انجام می‌شود |

برای محیط‌های دیگر [`.env.production.example`](../.env.production.example) و
[`.env.staging.example`](../.env.staging.example) نقطهٔ شروع‌اند. پس از پر
کردنشان این را بزنید — همان چیزی که در استقرار هم اجرا می‌شود:

```bash
php artisan env:check --env=production
```

## قراردادهایی که تست‌ها اجبار می‌کنند

این‌ها سلیقه نیستند؛ هرکدام تستی دارد که نقضش را قرمز می‌کند.

**اعتبارسنجی در `FormRequest`، نه در کنترلر.** `ArchitectureTest` هر
کنترلری را که `$request->validate()` داشته باشد می‌گیرد. دلیلش در
[`BaseFormRequest`](../app/Http/Requests/BaseFormRequest.php) نوشته شده.

**هیچ‌جا `Storage::disk('local')` ننویسید.** همه‌چیز از
[`PrivateFiles::disk()`](../app/Support/PrivateFiles.php) می‌گذرد.
⚠️ دیسکِ هاردکد یعنی با دو گره، فایلی که روی یکی آپلود شده از دیگری ۴۰۴
می‌گیرد — و چون به انتخابِ متعادل‌کننده بستگی دارد، خرابی **متناوب** است.
`ScalabilityTest` این را می‌گیرد.

**سقفِ هشدارِ لینت فقط در `package.json`.** اگر CI عددِ خودش را بنویسد، دو
عدد از هم واگرا می‌شوند.

**بودجهٔ کوئری.** `ScalabilityTest` هر مسیرِ داغ را با دو حجمِ داده اجرا
می‌کند و تعدادِ کوئری نباید رشد کند. اگر رابطه‌ای را eager-load نکنید،
همین‌جا قرمز می‌شود.

**بودجهٔ باندل.** `tests/js/bundleBudget.test.ts` اندازهٔ بارگذاریِ اول را
سقف‌دار کرده. برای دیدنِ تفکیک:

```bash
node scripts/analyze-bundle.mjs
```

**پیامک فقط برای کد یک‌بارمصرف.** به‌جز سهمیهٔ ماهانهٔ مدیر مجتمع، هیچ
پیامکِ دیگری فرستاده نمی‌شود. یادآوری‌ها اعلانِ درون‌برنامه‌ای‌اند.
`DocumentationTest` حتی وعده‌دادنش در مستندات را هم می‌گیرد.

**ایمیل اصلاً استفاده نمی‌شود.** هیچ مسیرِ خروجیِ ایمیلی در محصول نیست.

### قراردادهای فرانت (مرحلهٔ پنجم)

این‌ها هم هرکدام محافظی دارند که نقضشان را قرمز می‌کند.

**مرزهای import.** وابستگیِ حلقوی ممنوع است؛ `shared/` هرگز از `features/`
وارد نمی‌کند؛ `features/` هرگز از `app/` وارد نمی‌کند؛ و هیچ ویژگی‌ای به
**درونِ** ویژگیِ دیگر دست نمی‌برد — چیزِ مشترک جایش در `shared/` است.
محافظ: `tests/js/importBoundaries.test.ts` (بدونِ پکیجِ تازه؛ گراف از
خودِ منبع ساخته می‌شود).

**حالت.** هیچ استوری `persist` نمی‌گیرد، و خروج باید **ناوبریِ واقعیِ
مرورگر** بماند (`window.location.assign`) — این تنها چیزی است که دادهٔ سرورِ
مانده در استورها را با کاربرِ قبلی می‌بَرَد. Context تازه بدونِ تصمیمِ
صریح اضافه نمی‌شود. محافظ: `tests/js/stateBoundaries.test.ts`.

**تفکیکِ مسئولیت.** هیچ کامپوننتی چهار دغدغه از این پنج را با هم ندارد:
API، اعتبارسنجی، انیمیشن، قالب‌بندی، و حالتِ پراکنده (بیش از چهار `useState`). محافظ:
`tests/js/componentResponsibility.test.ts`.

**ایمنیِ نوع.** `any` ممنوع است؛ ادعای دولایه (`as unknown as`) ممنوع است؛
`JSON.parse(...) as T` بدونِ بررسی ممنوع است؛ و هر `queryFn` باید
`({ signal })` بگیرد تا با unmount و تغییرِ مسیر لغو شود. محافظ:
`tests/js/typeSafety.test.ts`.

**دادهٔ `localStorage` خارجی است.** `useLocalStorage` پارامترِ سومِ
**اجباری** دارد — نگهبانی که شکلِ داده را در زمانِ اجرا بسنجد:

```ts
const [history, setHistory] = useLocalStorage<HistoryEntry[]>(KEY, [], isHistory)
```

**پارامترِ آدرس با ادعای نوع خوانده نمی‌شود.** `params.get('x') as T` ممنوع
است؛ مقدار با یک نگهبان سنجیده می‌شود. محافظ: `tests/js/formsAndRoutes.test.ts`.

**فرمِ واقعیِ مرورگر هم باید قفل شود.** فرمی که با `method="POST"` مستقیم به
سرور می‌رود `isSubmitting` ندارد؛ دکمه‌اش را خودتان پس از ارسال غیرفعال
کنید و روی `pageshow` آزادش کنید تا دکمهٔ back آن را مرده رها نکند.

**پنجره‌های روی صفحه.** هر Modal، کشو یا لایت‌باکس `role="dialog"` و
`aria-modal` می‌گیرد، Escape می‌بندد، و Focus را با `useFocusTrap` نگه
می‌دارد و پس از بستن برمی‌گرداند. محافظ‌ها:
`tests/js/focusTrap.test.tsx` و `tests/js/keyboardReach.test.tsx`.

**حریمِ خصوصی و ایندکس (فاز ۷).** سرویسِ تحلیلی و گزارشِ خطا فقط **مسیر**
می‌گیرند، نه کوئری. هیچ عددِ مالی (مبلغ، مانده) به `trackEvent` نمی‌رود.
Clarity و GTM فقط در نقطه‌های ورودِ بازاریابی (`initObservability({ marketingTags: true })`)
و CSPِ صفحهٔ خصوصی هم اجازه‌شان را ندارد. صفحهٔ عمومیِ تازه تا در
`SeoController::PUBLIC_PATHS` نیاید noindex است — عمداً. فرمی که مرورگر به
دامنهٔ دیگری می‌فرستد باید `SecurityHeaders::allowFormTarget` را صدا بزند،
وگرنه `form-action` بلاکش می‌کند. `VITE_*` در متنِ باندل می‌نشیند؛ راز هرگز.
محافظ‌ها: `tests/js/privacySurface.test.ts`، `tests/Feature/PrivacyAndIndexingTest.php`
و `tests/Feature/GatewayFormActionTest.php`.

**سقفِ نرخ و درگاه (فاز ۹).** هر مسیرِ `/api` خودبه‌خود زیرِ سقفِ سراسریِ
`api` است؛ مسیری که هزینه یا آسیبش به دیگران می‌رسد (پیام، پیامک، پرداخت،
آپلود) سقفِ **ویژه** هم می‌خواهد و در `docs/LOAD_TESTING.md` ثبت می‌شود —
تست هم‌سانی‌اش را می‌سنجد. مسیرِ تغییردهنده‌ی وب بدونِ سقف تست را قرمز
می‌کند. درگاهِ تازه باید تأییدِ بانک را به **سفارشِ خودمان** گره بزند
(شماره‌ی سفارش و مبلغ)، هرگز به مقدارِ بازگشت اعتماد نکند، و تسویه را از
`TrackingCodes::exclusively` بگذراند. مسیری که باید در حالتِ تعمیر باز
بماند، در `EnsureNotInMaintenance::OPEN_ROUTES` می‌آید. محافظ‌ها:
`GatewayForgeryTest`، `AbusePreventionTest` و `MaintenanceModeTest`.

**فهرست، خطا، آپلود و تاریخ (فاز ۶).** مسیری که `paginate()` می‌دهد، در
صفحه‌اش `<Pager>` و `page` در آدرس می‌خواهد — `PaginationContractTest`
مسیرها را از کدِ کنترلر کشف می‌کند. خطای صفحه با `<ErrorState error={error} />`
نه رشته، تا از نگاشتِ مرکزیِ `errorUx` بگذرد. آپلود با `useUpload` و
`<UploadProgress>`، و فایل پیش از ارسال با `uploadProblem` و همان فهرستِ
قالبِ سرور (`RECEIPT_EXTENSIONS` یا `ATTACHMENT_EXTENSIONS`). هر تاریخ و
ساعتِ شمسی از `App\Support\Jalali` می‌گذرد که به وقتِ تهران تبدیل می‌کند؛
ذخیره همیشه UTC است.

**مرورگر و موبایل (فاز ۸).** کپی فقط با `copyText` از
`shared/lib/clipboard.ts` و نتیجه‌اش به کاربر گفته می‌شود — `browserCompat`
صدا زدنِ مستقیمِ `navigator.clipboard` را رد می‌کند. رفتن به صفحه‌ی ورود فقط
با `leaveToAuth()`؛ ناوبریِ مستقیم به `/auth` دو ناوبری می‌سازد و همان تست
ردش می‌کند. ناحیه‌ی اسکرولِ درونی با `overflow-y-auto` خودبه‌خود
`overscroll-behavior: contain` می‌گیرد (جز `<main>`)؛ فیلدها در نمای لمسی
دستِ‌کم ۱۶ پیکسل‌اند؛ ارتفاعِ تمام‌صفحه با `dvh` و پشتوانه‌ی `vh`.
`controllerchange`ِ نصبِ اول صفحه را بار نمی‌کند — فقط به‌روزرسانی.

**محیطِ آزمونِ سرتاسری.** روی دیتابیسِ **تازه**: `migrate`، `DemoSeeder`،
`otp_disabled`، سپس `E2eSeeder` (کیفِ سه مالک)، با `SUBSCRIPTION_GATEWAY=sandbox`
و `PAYMENT_SANDBOX_ENABLED=true` — همان کاری که CI می‌کند. ⚠️ دیتابیسِ
تکراری قبض‌های پرداخت‌نشده‌ی نمایشی را مصرف می‌کند، و اجراهای پیاپی به
سقفِ نرخِ ثبت‌نام می‌خورند (۴۲۹)؛ کشِ **همان دیتابیسِ آزمون** را پاک کنید.
سفرِ امنیت (`security-journey`) `AUTH_PASSWORD_TIMEOUT=5` می‌خواهد تا پنجره‌ی
رمز واقعاً دیده شود.

**نشست و عملیاتِ حساس (فاز ۱۰).** مسیرِ تازه‌ای که کاری برگشت‌ناپذیر یا
مقصدِ پول/داده/اسکریپت را عوض می‌کند، میدل‌ورِ `reauth` می‌گیرد و در
`ReauthenticationTest::GUARDED` نوشته می‌شود؛ اگر فقط بخشی از یک فرم حساس
است، مثلِ `SettingController::touchesMoneyRoute` در خودِ کنترلر
`PasswordConfirmation::ensure()` صدا زده می‌شود. فرانت کاری نمی‌کند: `api()`
پنجره‌ی رمز را باز می‌کند و درخواست را دوباره می‌فرستد (پیوندِ معمولیِ
مرورگر، مثلِ دانلود، پیش از رفتن `ensureRecentPassword()` را صدا می‌زند). در
تست، `withConfirmedPassword()` فقط برای تست‌هایی است که موضوعشان خودِ عملیات
است. شناسه‌ی نشست هرگز در پاسخ نمی‌آید (`SessionRegistry::publicId`). رفتن به
ورود فقط با `leaveToAuth()` و کدِ دلیل، نه متن. هر راهِ ورودِ تازه از
`Auth::login` بگذرد تا رویدادِ `Login` ساعتِ نشست و تاریخچه را بگذارد، و نوعش
را در `auth.login_event`ِ درخواست بنویسد.

**بلاگ و صفحه‌ی عمومیِ سرورساید (فاز ۱۱).** `body_html` فقط از
`BlogWriter` → `BlogRenderer` نوشته می‌شود؛ هر مسیرِ تازه‌ای که متنِ مقاله را
عوض کند باید از همان بگذرد. خواندنِ عمومی فقط از `BlogPost::visible()`. صفحه‌ی
عمومیِ تازه‌ای که ایندکس می‌شود: `SeoController::isIndexable` و نقشه‌ی سایت؛
پیشوندِ تازه‌ی سرورساید را از مسیرِ فراگیرِ SPA در `routes/web.php` بیرون
بگذارید تا آدرسِ ناشناخته‌اش ۴۰۴ِ واقعی بگیرد. ⚠️ در Bladeِ صفحه‌ای که
`layouts.public` را گسترش می‌دهد، نامِ متغیرِ حلقه نباید با متغیرهای قالب
(`$entry`، `$seo`، `$base`، `$current`، `$breadcrumbs`) یکی باشد — نشت می‌کند.
در تست، میزبانِ جعلی با آدرسِ کامل (`http://evil.example.com/...`) ساخته
می‌شود، نه `withHeader('Host')`.

**پیام‌رسان (فاز ۱۲).** پیام فقط از `MessageSender` نوشته می‌شود — همان‌جا
مجوز، `client_id`، تراکنش، پیوست و نوشتنِ دوگانه‌ی `audience` است. گفت‌وگو را
با `ConversationDirectory` بیابید یا بسازید (یافتن یا ساختن، امن در برابرِ
هم‌زمانی)، نه `Conversation::create`. دیدن با `Conversation::visibleTo` و
`Message::visibleTo`، و هر دو با `currentUnits()` — نه `units()`، که واحدِ
قبلیِ مستأجرِ رفته را هم دارد. ⚠️ در تست، `assertSee`/`assertDontSee` روی
پاسخِ JSON برای متنِ فارسی پوچ است (JSON آن را `\uXXXX` می‌کند)؛ روی
`json_encode($response->json(), JSON_UNESCAPED_UNICODE)` بسنجید.

**رنگ و اندازه.** رنگِ وضعیت فقط از توکن‌های `--tone-*` و `--state-*` می‌آید
(که در حالتِ تیره بازتعریف می‌شوند)، نه hex. اندازهٔ فونتِ دلخواهِ **تازه**
پذیرفته نمی‌شود و شمارِ موجود فقط کم می‌شود. مبلغ و تاریخ را خودتان
قالب‌بندی نکنید؛ از `resources/js/shared/lib/format.ts` استفاده کنید. محافظ:
`tests/js/designTokens.test.ts`.

## افزودن یک قابلیت

مسیرِ معمول برای یک قابلیتِ سرتاسری:

1. **مهاجرت** در `database/migrations/`. اگر جدول به مجتمع تعلق دارد،
   `complex_id` بگذارید و مدل را `BelongsToComplex` کنید — `ComplexScope`
   خودش جداسازیِ مستأجرها را اعمال می‌کند.
2. **مدل** در `app/Models/`.
3. **FormRequest** در `app/Http/Requests/`.
4. **کنترلر** در `app/Http/Controllers/Api/`.
5. **مسیر** در `routes/api.php`. ⚠️ مسیرهای عمومی را **پیش از** روتِ
   فراگیرِ `web.php` ثبت کنید؛ آن روت هر مسیرِ دیگری را با `view('spa')` و
   کدِ ۲۰۰ جواب می‌دهد و میان‌افزارتان اصلاً اجرا نمی‌شود.
6. **تست** در `tests/Feature/`.
7. **شکلِ پاسخ.** اگر مسیرِ تازه دادهٔ خواندنی برمی‌گرداند، آن را به
   `criticalEndpoints()` در `tests/Feature/ResponseShapeTest.php` اضافه کنید،
   دادهٔ **واقعی** (نه فهرستِ خالی) در `setUp` بسازید، و اسنپ‌شات را با
   متغیرِ محیطیِ `SHAPE_SNAPSHOT` برابرِ ۱ بازتولید و **بازبینی** کنید.
   ⚠️ `tests/fixtures/api-response-shapes.json` خروجیِ تولیدشده است؛ دستی
   ویرایشش نکنید. محافظ نمی‌گذارد شکلِ خالی ثبت شود.
8. **فرانت** در `resources/js/features/<name>/`.

اگر قابلیت باید بتواند بدونِ استقرارِ دوباره خاموش شود، یک پرچم در
[`config/features.php`](../config/features.php) تعریف کنید و مسیرش را با
میان‌افزارِ `feature:<key>` ببندید.

### انتظارِ این مخزن از یک تست

هر تستی که برای گرفتنِ یک باگ نوشته می‌شود، باید **ثابت شود که واقعاً
می‌گیردش**: باگ را عمداً برگردانید و ببینید تست قرمز می‌شود. این عادت در
این پروژه بارها تستِ پوچ پیدا کرده — تستی که سبز بود و هیچ چیزی را
نمی‌سنجید.

⚠️ **دامِ تکرارشونده:** تستی که متنِ سورس را می‌گردد، کامنتِ توضیحی را هم
می‌بیند. اگر کامنت همان الگویی را بنویسد که تست ممنوع کرده، تست روی کدِ
درست قرمز می‌شود یا روی کدِ خراب سبز می‌ماند. پیش از جستجو کامنت‌ها را پاک
کنید، با **دو الگوی جدا**:

```php
$source = (string) preg_replace('#/\*.*?\*/#s', '', $source);
$source = (string) preg_replace('#^\s*//.*$#m', '', $source);
```

یکی‌کردنشان با پرچمِ `s` باعث می‌شود `//.*$` کلِ فایل را ببلعد.

### نکته‌های محیطِ تست

- ⚠️ `User::factory()` کاربرِ **غیرفعال** می‌سازد. بدونِ
  `'is_active' => true` هر درخواستِ احرازشده ۴۰۳ می‌گیرد و تست به‌ازای
  دلیلِ اشتباه سبز می‌شود.
- ⚠️ هرگز `DB::purge()` روی اتصالِ پیش‌فرض نزنید؛ تراکنشِ `RefreshDatabase`
  روی همان اتصال باز است و کلِ کلاس با
  `cannot start a transaction within a transaction` می‌خوابد.
- ⚠️ `putenv()` به `env()` لاراول نمی‌رسد. برای تغییرِ تنظیمات در تست
  `config()` را عوض کنید.

## مستندات

مستندی که دروغ بگوید بدتر از نبودنش است. برای همین `DocumentationTest`
ادعاهای **قابلِ‌سنجش** را می‌سنجد: هر دستورِ artisan، هر اسکریپت npm، هر
مسیرِ فایل و هر متغیرِ محیطی که در مستندات آمده باید واقعاً وجود داشته
باشد، و `public/openapi.json` باید با مسیرهای واقعی هم‌خوان بماند.

اگر مسیرِ API اضافه کردید:

```bash
php artisan openapi:generate
```

و خروجی را کامیت کنید — وگرنه تست قرمز می‌شود.

⚠️ **عددی که با هر کامیت عوض می‌شود در مستندات ننویسید.** شمارشِ
هاردکدشده‌ی تست‌ها فقط تا کامیتِ بعدی درست می‌ماند؛ بنویسید **چطور**
بشمارند، نه چند تا هست. (`DocumentationTest` خودش این را می‌گیرد — و بله،
نسخه‌ی اولِ همین بند با نقلِ یک عددِ نمونه، تست را قرمز کرد.)

## قواعدِ فرادستِ مرحلهٔ دوم

این هفده قاعده از فایلِ «ایرادات مرحله دو» می‌آیند و **مرحله نیستند** —
روی هر تغییری از این به بعد اعمال می‌شوند. نقشهٔ کاملشان در
[STAGE2_AUDIT_MAP.md](STAGE2_AUDIT_MAP.md) بندهای ۳۰۹ تا ۳۲۵ است.

### پیش از هر تغییر، این نُه مورد را بررسی کنید

```
تغییر
 ↓ Regression نسازد
 ↓ امنیتِ قبلی تضعیف نشود
 ↓ کاراییِ قبلی کم نشود
 ↓ یکپارچگیِ داده آسیب نبیند
 ↓ PWA و Offline/Update خراب نشود
 ↓ معماری بی‌دلیل عوض نشود
 ↓ تست‌های قبلی سبز بمانند
 ↓ Clean Code / TypeScript / ESLint / Formatting رعایت شود
 ↓ وابستگی‌ها هم به‌روز شوند (تست، مستند، تایپ، قراردادِ API)
```

### ⚠️ «کد نوشته شد» با «انجام شد» یکی نیست

هیچ موردی صرفاً به‌خاطرِ نوشته‌شدنِ کدش **COMPLETED** اعلام نمی‌شود. هر
مورد باید چهار گام را طی کند:

**۱. بررسی → ۲. پیاده‌سازی → ۳. تست → ۴. Verification**

اگر Verification ممکن نباشد، وضعیتش **NOT VERIFIED** می‌ماند — نه
«انجام شد». همهٔ این موارد در R72 با نُه فیلد گزارش می‌شوند: نام، دلیل،
نیازِ Verification، نیاز به زیرساختِ خارجی، نیاز به سرویسِ ثالث، نیاز به
تستِ انسانی، نیاز به محیطِ محصول، سطحِ ریسک، و پیشنهادِ دقیق.

### قواعدِ ثابت

**امنیت بر راحتیِ توسعه مقدم است.** هیچ میان‌بُرِ امنیتی برای ساده‌تر شدنِ
کار یا رابطِ کاربری ساخته نمی‌شود.

**دادهٔ کاربر و مالی Critical است.** اطلاعات کاربر، شخصی، احراز هویت،
پرداخت، کیف پول، تراکنش، قبض، مجتمع، پیام، سند و سیاههٔ ممیزی بدونِ دلیل
حذف، Overwrite یا Hard Delete نمی‌شوند.

**Business Logic بدونِ دلیل تغییر نمی‌کند.** اگر برای رفعِ مشکلی لازم شد:
① تغییر را مشخص کن ② دلیلش را بنویس ③ تأثیرش را روی بقیه بررسی کن
④ تست‌ها را به‌روز کن.

**از Overengineering پرهیز کن.** هیچ کتابخانه، الگو، کش، صف، WebSocket،
SSE، Redis یا بهینه‌سازی صرفاً «برای اینکه باشد» اضافه نمی‌شود. اگر لازم
نیست، استفاده نکن و **دلیلش را در گزارش بنویس**.

**پیش از Refactorِ بزرگ، وضعیتِ فعلی را حفظ کن.** تغییر را مرحله‌ای انجام
بده، پیش و پس از آن تست بگیر، کامیت‌های منطقی و قابلِ‌بازگشت بساز، و هیچ
فایل، مهاجرت، کامپوننت، API یا ساختارِ دیتابیسی را بدونِ بررسیِ
وابستگی‌هایش حذف نکن.
